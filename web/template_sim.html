What you are looking at

Every frame is processed from scratch — nothing is tracked or carried between frames. The sensor is a Velodyne HDL-64E at 10 Hz; playback at 1× is real time.

The three colour groups map directly onto the problem statement's categories. Terrain is the ground surface recovered by per-sector plane fitting. Static obstacle is any non-ground cluster the network classifies as background — walls, poles, vegetation, parked structures. Car, Pedestrian and Cyclist are the dynamic-capable classes, drawn with their predicted 3D boxes.

The greyed-out region is deliberate. KITTI only annotates inside the camera frustum, so the model was only ever trained on clusters within roughly ±40° of forward. Classifying the full 360° would be running it out of distribution and presenting the output as if it were trustworthy. Ground removal runs everywhere; clustering and classification run only where the model is valid, and everything else is drawn as unscored.
"Dynamic" here means class, not motion. A parked car is coloured as a Car. Distinguishing moving from stationary requires comparing consecutive ego-motion-compensated sweeps — the residual-image approach from LiDAR-MOS — which this pipeline does not yet do. The data to build it is present: this drive has 108 consecutive frames with GPS/IMU poses.
